# AI 标注用户指南

本软件用于本地矩形目标检测数据的图片标注、YOLO 训练、AI 草稿复核，以及
MaixCAM-Pro/MaixCAM2 模型转换。首版不支持分割、OBB、关键点、外部 `.pt`
导入或外部图片引用。

## 1. 新建项目与导入图片

1. 选择“新建项目”，指定一个本地项目目录。
2. 在右侧“类别”区域添加并启用本项目需要的类别。
3. 选择“导入图片”。支持 JPG/JPEG、PNG、BMP 和 WebP。
4. 软件把图片复制到项目的 `images/`，按 SHA-256 去重，并统一 EXIF 方向。
   损坏或无法识别的文件会跳过并写入导入报告。

项目中的 `annotations.db` 是标注的唯一编辑真源。YOLO `.txt` 只在生成不可变
训练快照或显式导出数据集时产生。

## 2. 人工标注

- `W`：切换矩形框工具。
- `D`：事务保存当前框，把图片标记为“人工已确认”，并进入下一张。
- `Delete`：删除当前选中的框。
- `Ctrl+Z` / `Ctrl+Y`：撤销 / 重做。
- 画布支持选择、移动、八方向缩放、缩放和平移；可在右侧改变选中框的类别。
- 输入框、下拉框或弹窗获得焦点时，`W`/`D` 字母快捷键不会触发，避免输入文字
  时误操作。

框坐标始终以原图像素 `x1/y1/x2/y2` 保存。图片没有框也可以按 `D` 确认为明确
负样本；第一次这样确认时软件会提示。仅浏览或关闭一张没有修改的图片不会重写
其标注状态。

三种复核状态的含义：

- `未复核（unreviewed）`：还没有人工确认。
- `AI 待复核（draft）`：AI 建议或尚未确认的编辑。
- `人工已确认（verified）`：用户明确按 `D` 确认；只有该状态能进入训练快照。

## 3. 机器学习运行环境

安装版优先使用安装目录中的独立 Worker，最终用户不需要另外安装 Conda。源码
运行时，点击训练页的“ML 环境”可以：

- 自动扫描 Conda 及 `conda env list` 中的候选环境；
- 手动选择 Conda 环境目录或具体的 `python.exe`；
- 检测 Python、PyTorch、TorchVision、CUDA、GPU、Ultralytics 和传统 YOLOv5
  后端是否兼容；
- 在用户明确确认后创建或修复名为 `yolo` 的环境。

环境检测通过不等于一定存在 GPU。训练参数中的设备可选择：

- `0`：默认值，明确使用第一块 CUDA GPU；没有可用 CUDA 时会阻止启动。
- `auto`：运行时优先选择 CUDA，CUDA 不可用时回退 CPU。
- `cpu`：明确使用 CPU。
- 检测到的其他 CUDA 设备，或手工输入 Ultralytics 支持的设备值。

如果训练时 GPU 没有反应，先查看环境检测中的
`torch.cuda.is_available()`/GPU 名称，再确认训练设备不是 `cpu`。Nuitka 编译、
Inno Setup 打包、图片导入和普通标注本来就是 CPU/磁盘任务，不会持续占用 GPU。

## 4. 模型与首次训练门槛

模型下拉框固定提供 8 项，默认选择 YOLO26n：

| 界面模型 | 预训练权重 | 后端 |
|---|---|---|
| YOLOv5n | `yolov5n.pt` | 传统 anchor-based YOLOv5 v7.0 |
| YOLOv5s | `yolov5s.pt` | 传统 anchor-based YOLOv5 v7.0 |
| YOLOv8n | `yolov8n.pt` | Ultralytics |
| YOLOv8s | `yolov8s.pt` | Ultralytics |
| YOLO11n | `yolo11n.pt` | Ultralytics |
| YOLO11s | `yolo11s.pt` | Ultralytics |
| YOLO26n | `yolo26n.pt` | Ultralytics |
| YOLO26s | `yolo26s.pt` | Ultralytics |

第一次成功训练前必须至少有 100 张不同的“人工已确认”图片。明确确认的无框负样本
计入 100 张，但项目必须至少有一个正样本，并且每个启用类别都必须有实例。未复核
的 AI 草稿不计数，也不会进入快照。类别实例相差 10 倍以上时会警告，但不会直接
阻止训练。

项目已有一次成功训练后，“重新训练”不再把 100 张作为硬门槛，但仍然只读取当前
人工已确认或人工复核完成的图片；至少需要一张确认图片、正样本以及每个启用类别的
实例。每次点击训练都会创建不可变快照，训练期间继续编辑项目不会改变该次快照。

## 5. 可调整的训练参数

点击“高级参数”可编辑参数并保存为命名预设。

| 参数 | 默认值 | 可用范围或含义 |
|---|---:|---|
| `imgsz` | 640 | 160～2048，必须是 32 的倍数；大于 1280 会提示显存风险 |
| `epochs` | 100 | 1～5000 |
| `patience` | 20 | 0～`epochs`；0 表示关闭早停 |
| `batch` | `auto` | `auto` 或正整数 |
| `device` | `0` | 自动、CPU 或检测到的 CUDA 设备 |
| `workers` | 0 | 0～32；Windows 出现加载兼容问题时建议保持 0 |
| `seed` | 42 | 用于可复现训练 |

数据划分默认是训练/验证 `80/20`。也可启用测试集，预设为 `70/20/10`，并自行
调整三个比例：

- 比例总和必须为 100%；
- 训练集和验证集必须大于 0；
- 三分模式下测试集必须大于 0；
- 划分使用固定 seed；预计任一启用分区少于 10 张时会警告指标可能不稳定；
- 实际划分清单会写入本次不可变快照。

数据增强默认全部关闭，可分别设置：

- 随机旋转：最大角度 0°～30°及发生概率；
- 随机模糊：3×3、5×5 或 7×7 高斯核及发生概率；
- 水平镜像和垂直镜像：分别启用并设置发生概率。

所有增强概率范围为 0%～100%。增强只影响训练快照，不会修改项目原图或人工框。

## 6. 官方权重、best.pt、last.pt 与恢复

每次新训练的起点由用户明确选择：

- “官方预训练权重”：默认且推荐；从当前所选型号的官方权重开始。
- “历史 `best.pt`”：选择一次历史成功运行中验证指标最优的 checkpoint，作为
  新训练的初始化权重。
- “历史 `last.pt`”：选择一次历史运行最后一轮的 checkpoint，作为新训练的
  初始化权重。

选择历史 `best.pt` 或 `last.pt` 时，必须同时选择对应历史运行。软件不会在下一次
训练中隐式沿用旧模型。

“恢复中断训练”与“从历史 `last.pt` 新训练”不同：恢复只允许原运行的同一数据
快照和同一参数继续执行，并校验原 `last.pt`；后者会创建一次新的训练运行。

训练在独立进程中执行。界面实时显示 epoch/batch 进度、ETA、box/class/DFL loss、
Precision、Recall、mAP50、mAP50-95、学习率、GPU/显存、日志、训练/验证预览、
混淆矩阵与曲线；事件和指标同步写入运行目录。CUDA OOM 时会自动降低 batch
重试一次，仍失败则保留日志并建议改用 n 型、降低 `imgsz` 或减小 batch。

## 7. AI 自动标注与人工复核

AI 自动标注不会在训练结束后自动启动：

1. 先查看训练指标。
2. 在“AI 标注”页选择一次成功运行的 `best.pt` 或 `last.pt`。
3. 调整置信度、NMS IoU，并决定是否跳过已完成图片以支持中断续跑。
4. 点击“AI 自动标注”。

任务只处理尚未人工确认的图片，并逐张把结果导入为“AI 待复核”草稿；没有检测到
目标也会记录为空建议。AI 结果不会覆盖人工框，重复恢复按逐图结果保持幂等。

自动标注完成后，应逐张检查并按需要移动、缩放、删除、补充框或更换类别，最后按
`D` 转为“人工已确认”。未按 `D` 的草稿严格排除在下一次训练之外。

## 8. MaixCAM-Pro 与 MaixCAM2 部署

部署只能选择本项目成功训练产生的 `best.pt` 或 `last.pt`。转换还需要 Docker
Desktop、可用 daemon/WSL2，以及对应的官方转换镜像；软件不会静默安装 Docker。

| 目标 | 默认静态输入 | 转换目标 | 最终模型 |
|---|---:|---|---|
| MaixCAM-Pro | 320×224 | TPU-MLIR `cv181x` INT8 | `.mud + .cvimodel` |
| MaixCAM2 | 640×480 | Pulsar2 `AX620E` INT8 | `.mud + .axmodel` |

部署向导允许选择：

- 成功运行及 `best.pt`/`last.pt`；
- 32～4096 范围内、32 的倍数的静态输入宽高；
- 当前项目中人工确认的量化校准图：MaixCAM-Pro 20～200 张，MaixCAM2
  20～100 张，默认按类别分布建议最多 100 张；
- MaixCAM2 的 NPU2、VNPU/NPU1 或双模式；
- 置信度、IoU、最大检测数、双缓冲和相机分辨率。YOLO26 是端到端输出，
  IoU/NMS 设置不生效。

每次转换同时生成纯模型包和含 `main.py` 的完整 MaixPy APP。转换临时目录必须是
短 ASCII 路径，最终包从全新的 staging 目录按白名单生成，不直接压缩训练目录。

包内禁止包含 `.pt`、`.onnx`、`.mlir`、`.npz`、校准图片、数据集、日志、Docker
文件、缓存、其他设备/分辨率/NPU 模式的产物或未选择的 checkpoint。打包后会重新
打开 ZIP，校验条目与 SHA-256；`deployment-report.json` 和 SHA-256 清单保留在
包外。

体积阈值采用十进制 `30,000,000` 字节，并分别检查 ZIP 文件大小和解压后部署文件
总大小。任一项**大于**阈值时，界面会显示超出字节数和大文件排行，并暂停等待
确认；用户选择“仍然生成”后可以继续。软件不会擅自删除必需模型文件。可尝试改用
n 型、降低部署分辨率、MaixCAM2 只保留一种 NPU 模式或移除可选图标。

没有完成对应真机加载、相机推理与稳定性测试的转换结果会保持
`needs_device_validation`，不能显示为已验证发布。更完整的格式和白名单说明见
[Maix 模型部署](MAIX_DEPLOYMENT.md)。

## 9. 项目与运行产物

典型项目目录：

```text
project.json
annotations.db
images/
thumbnails/
runs/
exports/
deployments/
```

每次训练的参数、快照、划分、seed、指标、日志、`best.pt` 和 `last.pt` 都保存在
独立运行目录。设备部署报告保存在部署包之外，便于追溯来源 checkpoint、类别顺序、
输入尺寸、转换器版本、校准集与文件哈希。

## 10. 0.1.1 标注维护与 MaixHub/VOC 导入

### 标注显示与框拖动

标注页顶部的“标注显示”按钮不会修改数据库、训练快照或导出结果，可随时切换：

- **完整显示**：显示绿色框、类别和 AI 置信度；
- **仅显示框**：只显示绿色框，适合类别文字遮住相邻钢球时复核；
- **全部隐藏**：框和文字都不显示，也不能误选、拖动隐藏的框。

拖动或缩放框时，类别文字会暂时隐藏，并在松开鼠标后按新位置重新绘制。这避免旧位置出现绿色残影或框线连接。

### 本次操作撤销与批量清空

- `Ctrl+Z`：撤销一步；
- `Ctrl+Alt+Z`：**全部撤销**当前图片本次打开后产生的人工修改。切换图片或重启软件后，该临时历史会自动清除；
- `Ctrl+Shift+Delete`：打开“删除所有标记”，可选择当前图片、勾选多图，或按当前筛选结果批量选择。

批量删除只清除标注框和对应的 AI 草稿状态，不删除原图、类别、训练模型或历史运行。执行前软件会在项目的 `backups/` 目录创建 SQLite 备份；如误删，可在“文件 → 恢复标注备份…”中选择备份恢复。

### 导入 MaixHub 已标注数据集

不要用“导入图片”读取 MaixHub 的已标注导出包，因为它只导入图片，不能读取 Pascal VOC 的 XML 框。请点击：

`文件 → 导入 MaixHub/VOC 已标注数据集…`

或左侧的“导入 MaixHub/VOC 已标注数据”按钮。选择包含 `images/`、`annotations/` 和 XML 标注的根文件夹后：

1. 选择“新建项目导入”，可把完整已标注数据集创建为独立项目；
2. 或选择“合并当前项目”，将 VOC 数据合入当前项目；
3. 在类别映射中保持现有名称 **小刚球**，不需要也不会被自动更正；
4. 确认预览中的图片数、框数和冲突数后再导入。

合并时，未确认图片或纯 AI 草稿可以由 XML 标注安全升级；人工确认、人工修改或混合标注的重复图片会保留原有标注并列入冲突报告，不会被静默覆盖。
