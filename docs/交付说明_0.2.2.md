# AI 数据集标注与训练维护版 0.2.2：维护说明

## 本次修复

- 将模型准备进度与 Epoch/Batch 训练进度彻底分离。下载或校验权重时显示文件名、字节数和百分比；真正进入训练前 Epoch 保持 `0/用户设置轮数`。
- 内置经过长度与 SHA-256 双重校验的 `yolo26s.pt`。下载器支持断点续传、服务器忽略 Range 时安全重下、最多三次重试、取消后续传和陈旧任务锁恢复。
- 同一时刻只允许一个训练任务。取消、失败、进程异常退出和软件重启后均恢复按钮与任务状态，不再把下载百分比或未完成的 Batch 误记为 Epoch。
- 修复“起点 → 选到这里 → 终点”的鼠标事件时序。正向、反向及同端点选择均包含首尾，保留此前 Ctrl 多选，并支持筛选状态下按项目全局编号选择隐藏图片。
- 增加“仅修改显示名称”和“完整重命名类别”两个独立入口。前者只改变界面；后者在数据库备份后保持类别 ID 与框关联不变，并影响之后的训练、导出和新部署包。
- 完整重命名会保留历史名称为 VOC 导入兼容别名。旧训练快照通过稳定类别 ID，或通过历史名称/data.yaml 安全映射到当前规范名称；无法验证映射时明确阻止部署，不进行猜测。
- 编号输入支持英文逗号 `,`、中文逗号 `，`、顿号 `、` 及混合输入；解析失败时整体拒绝，不部分改变选择。
- 项目数据库结构正式升级到版本 5。首次打开版本 4 项目时先生成 `before-schema-v4-to-v5` 备份，再迁移类别历史名称表。

## 数据兼容与覆盖升级

- 0.2.2 继续使用维护版 0.2.x 的 AppId、安装目录、快捷方式和用户数据身份，可直接覆盖维护版 0.2.1。
- 早期原始软件使用不同身份，不会被本安装包卸载或覆盖。
- 现有项目、图片、标注、模型和部署产物不会被删除。
- 历史模型、历史训练快照和已经生成的部署包不会被原地改写；完整重命名只作用于当前项目及之后新生成的产物。

## 关键操作

1. 区间多选：单击起点，点击“选到这里”，再单击终点。
2. 仅改界面文字：选中类别，输入新名称，点击“仅修改显示名称”。
3. 改训练/导出/部署类别名：选中类别，输入新名称，点击“完整重命名类别”，阅读影响范围并确认。
4. 编号选择可输入 `1-50,88,900-999`、`1-50，88，900-999` 或 `1-50、88、900-999`。

## 验收基线

- Python/Qt 自动回归测试通过；GPU 专项测试需在明确启用 GPU smoke 开关后执行。
- 构建、安装器、源代码发布包和安装烟测只允许携带唯一、固定哈希的 `model-seed/yolo26s.pt`，其他 `.pt/.onnx/.engine` 仍被拒绝。
- 正式覆盖安装前应关闭维护版程序，并对当前项目数据库执行 SQLite 一致性备份。
